# Batch A, November 2026 — the plan and its order

Agreed with Dewi 2026-11-05/06 from his spitball list, every unread diagnostics report since 30 October, the
proofs of concept on the LG TV, the ✨ Ask spike, five reuse scouts and a review of the whole batch. Each item has its own file in this folder; each ships on its
own (gate, tests, docs, emulator look, push, CI watched). The batch ends with the soak against the release before it,
an Opus review and Haiku consistency sweeps.

## How this batch runs (Dewi, 2026-11-06)

- **Code first, tests after**, for this batch only: every item is written, compiled, checked with detekt and the
  existing tests, committed and **pushed as it goes** so Dewi can try it. New tests, emulator looks and TV checks come
  in one testing stretch after the code. A bug fix's test is still proven red, by running it on the commit before the
  fix. If CI's coverage gate blocks a release, that piece's tests are written straight away.
- **Standing permissions for this batch (Dewi, 2026-11-06):** wake the LG and cast short silent test clips at low
  volume (3%, restored after) whenever a casting item needs checking, daytime only, checked with Pi webcam stills
  cropped to the TV and deleted after; add `jq` to the AI container and `pychromecast` to the Pi service; up to three
  Sonnet builder agents in parallel, each in its own worktree, on items that touch different files, reviewed and
  merged by the main session.
- **A consistency sweep after every phase** (Dewi, 2026-11-06: "i want consistency"): a Haiku pass checks the phase's
  changes across every list, way in and kind of item; what holds up is fixed before the next phase. Phases 1-3 get one now.
- **An extra soak after phase 2** (the bug fixes touch playback and casting most), as well as the soak at the end.
